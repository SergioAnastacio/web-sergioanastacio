# Sergio Anastacio Website - Project Summary

## Purpose

`sergioanastacio.com` is the public website for Sergio Anastacio. The project is designed as a static-first personal and professional hub for:

- Personal brand and professional presence.
- Mobile app landing pages for App Store and Google Play.
- Support, privacy, and terms URLs required by app stores.
- Portfolio and service positioning for clients, recruiters, and collaborators.

The MVP intentionally avoids backend functionality. Contact uses `mailto:` links, and app/legal pages are generated statically.

## Current Status

- Framework: Astro.
- Hosting target: GitHub Pages.
- Deployment: GitHub Actions from `main`.
- Working branch: `dev`.
- Domain: `https://sergioanastacio.com`.
- DNS provider: Cloudflare.
- Sitemap: generated by `@astrojs/sitemap`.
- React support: enabled through `@astrojs/react`.
- Tailwind support: enabled through `@tailwindcss/vite`.
- Component library: no external component library is currently used.

React is currently used only as an isolated Astro island in the home hero. The site remains Astro-first and static-first.

## Tech Stack

Runtime and build:

- Astro `7.x`
- React `19.x`
- Tailwind CSS `4.x`
- `@astrojs/sitemap`
- GitHub Actions
- GitHub Pages

Development scripts:

```bash
npm install
npm run dev
npm run build
npm run preview
```

The build script disables Astro telemetry to avoid a Windows/libuv assertion seen locally after successful builds:

```bash
cross-env ASTRO_TELEMETRY_DISABLED=1 astro build
```

## Data Model

Centralized data lives in:

- `src/data/site.ts`: domain, emails, navigation, GitHub URL, avatar, mail helpers.
- `src/data/apps.ts`: app catalog, app details, FAQ, changelog, privacy, terms.
- `src/data/projects.ts`: portfolio/case study content.

This keeps app and portfolio expansion simple: add data first, and dynamic Astro routes generate the pages.

## Design Direction

Current visual direction:

- Quiet professional interface.
- Static-first pages with limited client JavaScript.
- React used only for selective interactive/animated visual islands.
- Tailwind available, but existing layout still uses project CSS in `global.css`.

ReactBits-style components are possible later, but should be added selectively to avoid making the whole site JS-heavy.
